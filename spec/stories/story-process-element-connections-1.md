## Acceptance Criteria

- [ ] **AC-01** — `IEntityConnectionCatalog` / `EntityConnectionCatalog` reads `EntityConnection` for a
  **host entity supplied as a constructor input, defaulting to `Activity`** (D2), resolved through
  `EntitySchemaResolver.ResolveByName` and kept as a *named* default — not an inline literal. It resolves
  each `ColumnUId` and returns `{ Name, Caption, DataValueTypeUId, ReferenceSchemaUId }`.
- [ ] **AC-02** — The candidate set is *registry ∪ element parameters ∩ host `Columns`*, computed **per
  element**. A global catalog that would accept `Application` on a Send email is a defect: the static
  parameter sets differ per user task.
- [ ] **AC-03** — The catalog reads the registry **with admin rights** (or via a plain `Select`). It must
  **not** copy the designer's `UseAdminRights = false` ESQ: the caller has already passed
  `CanManageProcessDesign` and the registry carries no user data. Failure mode being avoided is an empty
  candidate list that presents as a validation bug.
- [ ] **AC-04** — The tag, wherever one is produced, is **derived** as `$"{host.Name}Connection"`. The
  literal `"ActivityConnection"` must not appear in the source — `Activity` has a column of exactly that
  name, so a literal invites a tag/column self-reference confusion.
- [ ] **AC-05** — `ConnectionCapability` holds the **explicit allow-list keyed on user-task schema
  Name/UId**, applied on write paths only, and refuses anything unlisted while naming the schema.
- [ ] **AC-06** — `ConnectionCapability` also owns the **effectiveness rule** (D3): `ActivityUserTask` →
  always; `EmailTemplateUserTask` → `CreateActivity == true` **or** manual send mode;
  `AutoGeneratedPage` / `PreconfiguredPage` / `UserQuestion` / `OpenEditPage` → `CreateActivity == true`.
  Manual-send email must evaluate **effective**, because `ManualEmailUserTaskSender.cs:56-69` has no gate.
- [ ] **AC-07** — `UserTaskDeprecationPolicy` implements `usageType == None ∥ name ∈ {SendEmailUserTask,
  EmailUserTask}` and resolves the user-task schema as `FindInstanceByUId(uid) ??
  FindInstanceFromMetaData(uid)`. A test must prove the metadata fallback is exercised — without it the
  predicate silently returns `Advanced` for everything and `CallUserTask` passes.
- [ ] **AC-08** — The deprecation policy lives **outside** `ConnectionCapability` and is not consulted by
  any connections refusal (D9 scope). Its consumers are `describe`'s `deprecated` flag and the
  build/`addElement` policy refusal.
- [ ] **AC-09** — Unit tests cover all of the above. **No test asserts caption content**: the fixture's
  `CreateLookupColumn` sets `Caption = new LocalizableString()` (empty).

## Implementation Notes


Names are `EntityConnection*`, **not** `ActivityConnection*` (D2) — renaming a class now is free, after
the names reach guidance and docs it is not.

Registry facts: keyed `(SysEntitySchemaUId, ColumnUId, Position)`; `Position` is always `0` in shipped
data, never NULL; the Activity root UId is `c449d832-a4cc-4b01-b9d5-8a12c42a9f89`. `Project` is appended
**after** the designer's sort (so it lands last) and only when the column exists — mirror that ordering,
and treat its absence as normal rather than an error.

Test fixture, from `C:/Projects/UnitTests`:

- `UnitTestUtilities.CreateLookupColumn:223-238` sets `UId = Guid.NewGuid()`,
  `ReferenceSchemaUId = referenceSchema.UId`, `ReferenceSchema`, `DataValueType = Lookup` — all non-empty,
  so the `ColumnUId`-keyed join is testable. `Caption` is **empty**.
- Prefer the extension `manager.CreateLookupColumn(targetSchemaName, columnName, lookupSchemaName)`
  (`:249-262`) — it **auto-creates** the referenced schema, which removes the ordering trap in
  `TestEntitySchemaManager.CreateEntitySchemaMock:316-328` (that path resolves the reference via
  `GetInstanceByName`, so mocking the referenced schema *second* NREs on `referenceSchema.UId`).
