**What is true** — templates never declare the record data source. On a live stand `BaseMobilePageTemplate` and
`BasePageTemplate` declare no data sources, and `MobilePageWithTabsFreedomTemplate` / `PageWithTabsFreedomTemplate`
declare only `AttachmentListDS`. A page generated by `create-app` therefore holds `PDS` and `primaryDataSourceName`
in its OWN body: a root `modelConfigDiff` merge on mobile, a full `SCHEMA_MODEL_CONFIG` on web. A replace write
(`sync-pages`, `update-page` replace) overwrites that body, so a body sent without it drops `PDS` while every
`PDS.*` binding stays, and both designers show the fields as unbound. `IPageDataSourceReferenceValidator` rejects
that write for web and mobile bodies alike.

**Why it is this way** — declarations follow `PageBundleBuilder.BuildConfig`, not the body's text: a layer with a
non-empty model config diff is applied over the base and its full `modelConfig` is ignored; a layer with an empty
diff has its full config deep-merged into the base. A web page's own full `SCHEMA_MODEL_CONFIG` therefore ADDS to the
template's sources (a binding to the template-only `AttachmentListDS` is valid). A `remove` of a data source, and a
merge below one the base lacks (`["dataSources", "PDS", "config"]`), declare nothing — `JsonPathDiffApplier.Merge` is
a silent no-op on a missing path. A merge into `["dataSources"]` declares only if the base or a root operation has a
`dataSources` object.

**What breaks if you ignore it** — the check reads the inherited base (replace mode: without the page's own body;
append: with it). An empty ancestor chain is a resolved base and comes back as `{}` from `BuildExcludedOwnBodyBase`;
only a failed read is `null`. If those two collapse again, the check fails open on exactly the standalone page it
exists for. When the base truly cannot be read (`validate-page` has no environment, auth or network failure) the
check passes and adds a "were not checked" warning — treat a pass without that warning as checked, and never as
proof when the warning is present.
