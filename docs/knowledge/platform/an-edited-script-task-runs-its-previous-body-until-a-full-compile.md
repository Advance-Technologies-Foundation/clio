**What is true** — a process with a script task has three runtime states, measured on the local .NET
Framework stand `Creatio` with CrtProcessBuilder 1.6.6.28 on 2026-09-25:

1. Saved, never compiled: starting it throws `Publish the "<process name>" process before starting it`.
2. Compiled: the body runs.
3. Body replaced through `setElement` after a compile: the PREVIOUS body keeps running, with no error and no
   warning anywhere. The run after the edit raised the old body's own `InvalidCastException`, which the new
   body could not raise.

The save is not what lags. `SysSchemaSource.Source` held the new body immediately after the modify: process
source is generated at SAVE time (`SchemaManager.InternalSaveSchemaInDb` → `GenerateSchemaSources`). What
lags is the compiled assembly. A changed-items build (`clio compile-configuration`, which is the designer
Publish's `WorkspaceExplorerService.Build`) finished in 12 s and left `Autogenerated/Src/<Process>.<Package>.cs`
with the old body; the full compile (`compile-configuration --all`, 20 min 43 s) rewrote it, and the next
run returned the new result.

**Why it is this way** — the runtime binds each script task to a method of the compiled
`<Process>MethodsWrapper` type by name (`ProcessComponentSet`, `ProcessModel.GetScriptTaskMethod`); the
"publish" check (`ProcessSchema.CheckCompiledMethodsInAssembly`) only asks whether that TYPE exists. Once it
does, nothing compares its methods with the saved source. Why the changed-items build skipped the edited
schema was not traced to a line; only the outcome was measured, once, on one stand.

**What breaks if you ignore it** — an agent that edits a script body, runs a changed-items or package
compile, and then tests the process sees the OLD behaviour and "fixes" code that was never the code
running. That is why the package's compile demand and every clio and guidance surface say a FULL
`compile-creatio` (no `package-name`), and why a stand check must confirm the new behaviour on a run. If a
later measurement shows the changed-items build picking up an edit, narrow the instruction then; until
then, the full compile is the only route observed to work.
