COMMAND TYPE
    Object rights

NAME
    get-column-rights - Read column permissions (per column, every role's access level denied/read/edit) for an object

SYNOPSIS
    get-column-rights --entity-schema-name <EntitySchemaName> [--column <ColumnCode>] [--grantee <SysAdminUnitId>] [OPTIONS]

DESCRIPTION
    Read-only companion of get-object-rights for the COLUMN (field-level) layer, from the same
    RightManagementService GetAdministratedObject read. Reports whether "Use column permissions" is
    ON for the object and, per column that has rows, every row in priority order.

    The object is named by its code (entity schema name), and the code always wins. When no object has
    that code, the object whose title it is is read, and the output says so; several objects with that
    title are refused and listed as 'title' (code: name). The object is shown by its title next to its
    code when its title differs from the code.

    Each column is shown by its code (resolved from the column's UId through the entity schema, every
    package layer included) with the caption the service returns. When the columns cannot be read, a
    warning says so and each column is shown by its UId and caption. Each row is shown as
    [position] grantee name (grantee id): denied | read | edit; position 0 is the highest. A level the
    service returns that is none of these is shown as unknown (N).

    Per object the output is one of:
      - "Column permissions: OFF" - every column is governed only by object and record permissions.
        Rows stored while the switch is OFF are listed after it.
      - "Column permissions: ON, and no column has a permission row."
      - "Column permissions: ON. Columns with rows:" followed by each column and its rows.
    The service does not store a column whose rows all grant edit, so such a column never appears.

    With --column only that column is shown; a column with no rows is reported as such. With --grantee,
    per column, the grantee's row is shown followed by the rows above it; in a column where the grantee
    has no row, every row of the column is listed. The command draws no coverage verdict.

OPTIONS
    --entity-schema-name
        The object to read: its code (entity schema name, for example UsrOrder), or its title when no
        object has that code. Required.

    --column
        Optional column code (for example UsrDescription): show only that column's rows.

    --grantee
        Optional SysAdminUnit id (role or user): per column, show its row and the rows above it (every
        row of a column where it has none). When omitted, every row is listed.

    -e, --environment
        Name of the registered environment to read.

EXIT CODES
    0   The read ran; the facts are printed.
    1   The entity schema name was missing or names no object by its code or its title, several objects
        have it as their title, the title lookup failed, --column was not a column code or names no column
        of the object, the columns could not be read for --column, --grantee was not a GUID, or the
        object's permissions could not be read.

EXAMPLES
    List every column with rows, in priority order:
        clio get-column-rights --entity-schema-name UsrOrder -e production

    Read one column's rows for one role:
        clio get-column-rights --entity-schema-name UsrOrder --column UsrAmount --grantee <role-id> -e production
