COMMAND TYPE
    Object rights

NAME
    get-object-rights - Read object operation permissions (read/create/edit/delete per role) for an object

SYNOPSIS
    get-object-rights --entity-schema-name <EntitySchemaName> [--grantee <SysAdminUnitId>] [--include-connected] [OPTIONS]

DESCRIPTION
    Read-only companion of set-object-rights. Reports the object's per-role operation permissions — the
    SysSchemaOperationRight / "Object permissions" layer (who may read/create/edit/delete ANY record of
    the entity). By default every role's row is listed; pass --grantee to focus on one role.

    The rows are listed in priority order, each with its [position] (0 is the highest). A user who is in
    several roles gets the operations of the highest matching row — decided per row, so a row with no
    operations denies them. Per object the output is one of: "administered by operation permissions"
    with its rows; "administered by operation permissions, with NO rows" (only holders of the "...any
    data" system operations reach it); or "not administered by operation permissions" — available to
    all INTERNAL users, external users reach it only through an explicit grant — followed by the rows
    that would start to decide once operation permissions are turned on.

    With --grantee the grantee's row is shown (each row with its own position when it has several), or
    "has NO row (no operations granted)", followed by the rows above it: for a user who is also in one of
    those roles, they decide first. The command draws no coverage verdict.

    With --include-connected the root object's own lookup objects are read too — the discovery step
    before granting: decide per object, then run one set-object-rights per object. Security and system
    lookups (SysAdmin*, SysUser*, SysSchema*, SysPackage*, SysSettings*, SysLic*, SysProcess*, Vw*,
    *Right/*Rights) are not read as connected objects and are named in a warning. A connected object that
    cannot be read, or a connected set that cannot be enumerated, is reported with a warning.

OPTIONS
    --entity-schema-name
        Object (entity schema) name to read (for example UsrOrder). Required.

    --grantee
        Optional SysAdminUnit id (role or user): show its row and the rows above it. When omitted, every
        row is listed.

    --include-connected
        Also read every object referenced by the root object's OWN lookup columns.

    -e, --environment
        Name of the registered environment to read.

EXIT CODES
    0   The read ran; per-object facts are printed. Connected objects that could not be read are reported
        with a warning.
    1   The entity schema name was missing or not a plain schema identifier, --grantee was not a GUID,
        the named (root) object was not found, or its rights could not be read.

EXAMPLES
    List every row of an object, in priority order:
        clio get-object-rights --entity-schema-name UsrOrder -e production

    Before granting a role access to an object and its lookups, read the role's rows on all of them:
        clio get-object-rights --entity-schema-name UsrOrder --grantee <role-id> --include-connected -e production
