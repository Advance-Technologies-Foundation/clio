COMMAND TYPE
    CI/CD commands

NAME
    push-pkg - Install package from directory you can use the next command:
               for non compressed package in current folder

DESCRIPTION
    push-pkg command can be used in CI/CD pipeline or in development
    when you need install package to a web application (website).

WEB FARMS
    On a Creatio web farm whose gateway sends only requests that carry the
    StickySession cookie to the design node (for example a Kubernetes
    deployment managed by Creatio Control Plane), register the environment on
    the shared application URL. clio runs the installation - upload, backup,
    install, installation log and restart - in one session, and obtains
    StickySession before the first upload, so these requests reach the design
    node. The user needs the CanManageSolution operation permission.
    Compilation requested with --force-compilation and the developer-mode
    package unlock run in sessions of their own and are not covered.

    On a web farm only the design node may change during an installation. When
    the session holds StickySession, clio asks the design-node probe before
    uploading: if the probe confirms the design node, the installation runs.
    While the gateway itself answers that the design node is unavailable (HTTP
    502, 503 or 504 - for example while it restarts after the previous
    installation), clio waits for it for up to 5 minutes and reports the wait
    once a minute. Any other answer - a common node answering the probe, a
    missing probe (HTTP 404), or a design node that did not come back in time -
    stops the command before anything is uploaded, with exit code 1 and the
    HTTP status the probe answered (or that it got no answer). A request that should start the session
    but does not succeed is reported as a warning. Publishing and rolling out
    the installed version to the common nodes remains a Control Plane step.

    On .NET Creatio, and when developer mode is on, clio restarts the
    application after a successful installation. A failed installation does
    not restart it. On a web farm clio then waits, for up to 5 minutes, until
    the restarted design node has gone down and answers again, so the next
    command of a pipeline can start right away. A design node not seen going
    down within a minute is accepted as soon as it answers; one that is not back
    within 5 minutes gets a warning, and the command still succeeds.

SYNOPSIS
    clio push-pkg <PACKAGE_NAME>

OPTIONS
    Package name (pos. 0) Name/path of package folder or path for zip or gz 
    package file

    --uri                   -u          Application uri

    --Password              -p          User password

    --Login                 -l          User login (administrator permission 
                                                                      required)

    --Environment           -e          Environment name

    --Maintainer            -m          Maintainer name

    --skip-backup                       Skip package backup before install only
                                        when explicitly set to true

EXAMPLE
    clio push-pkg <PACKAGE_NAME>
        install package from directory you can use the next command: for non 
        compressed package
        in current folder

    clio push-pkg package.gz
        install package from .gz packages you can use command

    clio push-pkg package.gz --InstallSqlScript false --InstallPackageData false 
            --ContinueIfError true --SkipConstraints false --SkipValidateActions false
            --ExecuteValidateActions false --IsForceUpdateAllColumns false
        install package from .gz packages, with options, you can use command

    clio push-pkg C:\Packages\package.gz
        install package from .gz packages you can use command

    clio push-pkg <PACKAGE_NAME> -r log.txt
        installation log file specify report path parameter

    clio push-pkg <PACKAGE_NAME> --skip-backup true
        install package without creating backup first; omitted option keeps
        the existing backup behavior

EXIT CODES
    0   The installation finished and nothing else in the run failed. Schemas the
        platform skipped because they were modified on the environment are reported
        as [WAR] warnings and do not fail the command: the package itself was
        installed.

    1   The installation actually failed, or clio could not reach the environment.
        The reason the platform reported and the package that failed are
        both named on the closing lines. A run that skipped a locally modified
        schema AND failed to compile also lands here: --continue-if-error is on by
        default, so one archive can carry both, and the closing line then names the
        compiler diagnostic. A package FOLDER whose Schemas/ or Data/ holds a
        folder without descriptor.json is refused before upload, with the full
        local path of each such folder and whether to delete it (only
        Localization files) or restore its descriptor.json; Creatio would
        reject it with "Invalid descriptor".
