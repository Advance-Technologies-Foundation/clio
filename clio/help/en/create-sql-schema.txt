COMMAND TYPE
    Development commands

NAME
    create-sql-schema - Create a new SQL script schema on a remote Creatio environment

ALIASES
    sql-schema-create

SYNOPSIS
    clio create-sql-schema [OPTIONS]

DESCRIPTION
    Creates a new SQL script schema on a remote Creatio environment via
    ScriptSchemaDesignerService. The schema is saved directly to the server;
    no local workspace files are created.

    The schema-name must start with a letter and contain only letters, digits,
    or underscores. The name must be unique within the environment.

OPTIONS
    --schema-name                      New SQL schema name (required)

    --package-name                     Target package name that will own the new schema (required)

    --caption                          Optional display caption; defaults to schema-name

    --description                      Optional schema description

    --caption-culture                  Override the culture for the generated
                                       caption (e.g. en-US, uk-UA). Precedence:
                                       override > profile culture > en-US.

    --uri                    -u       Application uri

    --Password               -p       User password

    --Login                  -l       User login (administrator permission required)

    --Environment            -e       Environment name

    --Maintainer             -m       Maintainer name

EXAMPLES
    clio create-sql-schema --schema-name UsrCleanupStaleRows --package-name Custom -e dev
        Create UsrCleanupStaleRows in the Custom package on the dev environment

    clio create-sql-schema --schema-name UsrCleanupStaleRows --package-name Custom --caption "Cleanup stale rows" -e dev
        Create with a display caption

    clio sql-schema-create --schema-name UsrCleanupStaleRows --package-name Custom --description "Nightly cleanup" -e dev
        Create with a description using the alias

NOTES
    ScriptSchemaDesignerService must be served by the target environment. When it
    is not, the endpoint answers with an empty body or an HTML error page; clio
    then reports which service, operation and URL answered, instead of a raw JSON
    parser message. clio's synchronous client does not expose the HTTP status, so
    the message says the status is unknown rather than quoting one.

    When the save answer is unusable, clio reads the schema back before reporting:
    a schema that was in fact created is reported as a success, a schema that is
    absent as a failure, and a failed read-back as an unverified outcome.
