NAME
    add-package - Add a package; --as-app also creates a localization schema and injectable resolver

DESCRIPTION
    Adds a package to the current workspace or local application structure.
    Refer to Commands.md for detailed scenarios and examples.

SYNOPSIS
    clio add-package <PACKAGE_NAME> [OPTIONS]

OPTIONS
    <PACKAGE_NAME>
        Package name to add, from 1 to 70 characters. Start with a letter or a
        non-lone underscore; then use only letters, digits, and underscores.

    -a, --as-app
        Create an application descriptor, a
        <SCHEMA_NAME_PREFIX><PACKAGE_NAME>LocalizableStrings source-code schema,
        and an injectable adapter over Creatio LocalizableString

    --schema-name-prefix <PREFIX>
        Prefix for the schema generated by --as-app. Omit it to read the
        SchemaNamePrefix system setting from the target environment. Write it as
        --schema-name-prefix "" to generate without a prefix on purpose; a value that
        is only whitespace is rejected as a typo

    -b, --build <CREATIO_BUILD_PATH>
        Optional Creatio build archive or extracted directory used to download
        build dependencies after creation

    -e, --environment <ENVIRONMENT_NAME>
        Optional environment list used for download-configuration scenarios

EXAMPLES
    clio add-package MyPackage -a
        Add an application package with localization-ready backend primitives

    clio add-package MyPackage -a -e env_nf,env_n8
        Add a package and download configuration from multiple environments

    clio add-package MyPackage -a --build C:\Builds\creatio.zip
        Add an application package and download configuration from a Creatio build archive

    clio add-package MyPackage -a --schema-name-prefix Usr
        Add an application package and name the generated schema UsrMyPackageLocalizableStrings
        without contacting Creatio

    clio add-package MyPackage -a --schema-name-prefix ""
        Add an application package and generate the schema unprefixed on purpose, for
        an environment whose SchemaNamePrefix is empty

NOTES
    Creatio validates the code of a generated schema against the SchemaNamePrefix
    system setting of the environment the package is loaded into, and refuses the
    schema when its code does not start with that value. Usr is only the
    out-of-the-box value; an environment may configure a different one or none.
    Beware which path tells you: installing the package with push-pkg and running
    compile-configuration both ACCEPT an unprefixed schema. The check fires when the
    package is loaded from the file system, which is what blocks compilation from the
    Creatio UI.

    The prefix is resolved in this order:
      1. --schema-name-prefix, when supplied. No Creatio request is made, so this is
         also the way to generate a correct package offline. An explicitly empty
         value means "no prefix" and is applied silently.
      2. The SchemaNamePrefix system setting of the environment named by -e. With no
         -e, the active environment is used. A comma-separated -e list names no
         single target, so it resolves no prefix.
      3. Otherwise the schema is generated with no prefix and a warning is printed.
    A package name that already starts with the resolved prefix is not prefixed
    again, so UsrMyPackage yields UsrMyPackageLocalizableStrings.

    Reading step 2 is a request to Creatio, and the resolved value is echoed with the
    environment it came from - check it, because a prefix read from the wrong
    environment is refused exactly like no prefix at all. When the environment does
    not answer, the command reports it, generates the schema unprefixed, and still
    creates the package; a host that silently drops packets costs about a minute
    before that happens, and one that accepts the connection and never answers has no
    clio-side deadline at all. Pass --schema-name-prefix to skip the request entirely.

    The generated <SCHEMA_NAME_PREFIX><PACKAGE_NAME>LocalizableStrings schema contains
    one example value, LocalizableStrings.PackageLevelExample.Value. Use this schema
    only for package-level backend values that have no more natural schema owner.

    Application code receives ILocalizableStringResolver through dependency
    injection. LocalizableStringResolver is the only generated primitive that
    constructs Creatio Core's concrete LocalizableString; it exposes current-
    culture, strict-culture, and fallback operations. Do not replace this boundary
    with a static accessor or a Helper interface.

    Keep page, process, object, and other schema-specific resources with the schema
    that renders or consumes them. The generated primitive is not a central
    localization registry.
